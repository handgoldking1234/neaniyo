# 투표 데이터

사이트는 두 곳의 투표를 합쳐서 보여줍니다.

| 위치 | 용도 | 배포 |
|---|---|---|
| `main` 브랜치 `data/polls.json` | 사이트와 함께 배포되는 기본 투표 | Vercel 배포됨 |
| `feed` 브랜치 `data/polls.json` | 자동 수집으로 계속 쌓이는 투표 | **배포 안 됨**. 사이트가 GitHub raw 주소에서 10분마다 직접 읽음 |

자동 수집 작업은 **feed 브랜치에만** 씁니다. Vercel 배포 횟수를 쓰지 않으므로 주말에도 그대로 돌아갑니다.

**예약 공개**: `at`이 아직 오지 않은 투표는 사이트에 보이지 않다가 그 시각에 자동으로 공개됩니다. 공개 간격은 **5분**입니다.

## 형식

```json
{
  "id": "f2611121405",
  "at": "2026-11-12T14:05:00+09:00",
  "cat": "연예",
  "sub": "음악·공연",
  "type": "vs",
  "q": "질문 (40자 이내)",
  "o": ["보기 1", "보기 2"],
  "desc": "배경 설명 2~4문장. 기사·게시글 문장을 옮기지 않고 직접 쓴 문장.",
  "src": [{ "title": "출처 · 직접 쓴 짧은 제목", "url": "https://..." }],
  "ai": ["보기 1을 고르는 쪽의 논리", "보기 2를 고르는 쪽의 논리"],
  "comments": true
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | O | feed는 `f` + 공개 시각 `YYMMDDHHmm`. 예: `f2611121405`. 중복 금지 |
| `at` | O | 공개 시각. 5분 단위(:00, :05 … :55), ISO 8601, 한국 시간(+09:00) |
| `cat` | O | 대분류 값(아래 표의 `cat`) |
| `sub` | O | 소분류(아래 표) |
| `type` | O | `vs`(보기 2개) 또는 `multi`(보기 3~4개) |
| `q` | O | 질문, 40자 이내 |
| `o` | O | 보기 배열, 각 20자 이내 |
| `desc` | 권장 | 배경 설명 2~4문장 |
| `src` | 권장 | 참고 링크 1~2개 |
| `story` | 사연만 | 사연(cat "사연")의 상황 설명 2~3문장 |
| `comments` | O | 모든 투표 `true` (한줄평 열기) |
| `ai` | **O** | 보기마다 그 보기를 고르는 쪽의 논리 한 줄(각 50자 이내, 보기 수와 같게). 투표 뒤 "AI 양쪽 의견 정리"로 보임. 어느 한쪽을 깎아내리지 말고 공정하게 |
| `v` | X | 득표 수. 비워 두면 0으로 시작 |

## 카테고리 (대분류 → 소분류)

| cat | 화면 이름 | 소분류 | 자동 수집 비율 |
|---|---|---|---|
| 연예 | 연예 | 음악·공연 · 드라마·영화 · 예능·유튜버 · 스포츠 · 게임 | 24% |
| 사회 | 사회 | 직장·노동 · 생활·안전 · 정치·정책 · 경제·재테크 · 부동산 · IT·테크 | 24% |
| 라이프 | 라이프 | 연애·결혼 · 육아·가족 · 음식·맛집 · 여행·여가 · 건강·운동 | 16% |
| 사연 | 사연·고민 | 연애 · 가족 · 직장 · 친구·인간관계 · 돈 | 12% (아래 '사연 쓰는 법') |
| 교육 | 교육 | 교육 이슈 · 유아 · 초등 · 중등 · 고등 | 12% |
| 밸런스 | 밸런스 | 밸런스게임 · 취향 | 12% |

2026-11-27 분류 정리: 경제·IT·패션·정치는 모두 `사회`로(소분류로 구분), 스포츠·게임은 `연예`로, 퀴즈는 올리지 않는다. 예전 값(경제·스포츠·IT·게임·정치·패션·쇼핑·아이돌·K팝 등)으로 올려도 화면에서 새 분류로 옮겨 보이지만, 새로 쓸 때는 위 표의 값만 쓴다.

**음악·공연 쓰는 법** (`cat: "연예", sub: "음악·공연"`)
- 팬이 아니어도 누구나 답할 수 있는 생활 속 음악 이야기를 쓴다: 노래방, 출퇴근 플레이리스트, 음원 구독료, 공연·뮤지컬 티켓값, 페스티벌, 버스킹, 이어폰, 옛날 노래 역주행, 축가·장례식 노래 같은 것.
- 아이돌 컴백·팬덤·시상식·직캠·팬사인회처럼 팬만 아는 주제는 **2시간에 1개 이하**로 줄이고, 그것도 일반 사람이 답할 수 있게 묻는다.
- `정치·정책` 소분류는 2시간에 1개 이하.

**골고루 올리기 규칙** (한 번에 채우는 2시간 24칸 기준)
- 연예·사회·라이프·사연·교육·밸런스는 **매번 1개 이상** 넣는다. 사연은 **2~3개**.
- 한 분류가 24칸 중 6칸(25%)을 넘지 않게 한다.
- 같은 분류가 연달아 오지 않게, 같은 소분류는 최근 12개 안에 두 번 오지 않게 섞는다.
- 넣기 전에 최근 하루(약 288개) 분포를 세어 보고, 위 비율보다 적은 분류부터 채운다(예전 값은 새 분류로 바꿔 센다).

**사연 쓰는 법** (`cat: "사연"`)
- 실제 사람의 글을 옮기지 않는다. 많은 사람이 겪는 **흔한 고민을 일반화한 상황**으로 직접 쓴다.
- `story` 필드에 상황 설명 2~3문장(150자 안팎)을 "~하는 상황이에요"처럼 3인칭·상황형으로 쓴다. 특정인의 실제 경험처럼 꾸미지 않는다.
- `comments: true` 를 넣어 한줄평을 받는다. `ai`도 다른 투표처럼 필수.
- 질문은 "~해도 될까?", "~어떻게 할까?"처럼 조언을 구하는 말투로. 보기는 양쪽을 같은 무게로.

같은 대분류가 연달아 공개되지 않게 섞습니다.

## 이슈를 찾는 곳

공개된 순위·목록에서 **주제(키워드)만** 가져오고, 글이나 기사 문장은 옮기지 않습니다.

- 실시간 검색 흐름: Google 트렌드 한국 급상승(RSS), 시그널 실시간 검색어 등 공개 순위
- 뉴스: 네이버·다음 많이 본 뉴스, 연예·스포츠 랭킹
- 커뮤니티: 네이트판 랭킹, 더쿠 HOT 등 공개 게시판의 **제목 흐름**만
- 영상·SNS: 유튜브 인기 급상승, 인스타그램·스레드·X에서 화제인 주제는 그것을 다룬 **기사**를 근거로 사용
- 네이버 카페·인스타그램·스레드처럼 로그인이 필요한 곳은 직접 수집하지 않는다

## 작성 규칙

- 실명 연예인의 열애·사생활·논란을 직접 묻지 않는다. 현상이나 제도로 바꿔 묻는다.
- 일반인이 등장하는 사건, 커뮤니티 사연을 그대로 옮기지 않는다. 주제를 일반화한다.
- 정치는 제도·정책 질문만. 정당·후보·정치인 이름 금지. 선거 기간에는 정치 투표를 올리지 않는다.
- 경제는 특정 종목·아파트 단지 이름 금지. "지금 팔 때일까?"처럼 시장 심리를 묻는 건 괜찮지만 답을 정해 주는 투자 권유 표현은 쓰지 않는다.
- 보기는 양쪽을 같은 무게와 말투로 쓴다. 한쪽을 비하하는 표현 금지.
- 사고·참사·범죄 피해 같은 비극적 사건은 투표 소재로 쓰지 않는다.
- 최근 3일 안에 올린 투표와 같은 주제는 다시 올리지 않는다.
- feed 파일은 최근 600개까지만 유지하고 오래된 것부터 지운다.
